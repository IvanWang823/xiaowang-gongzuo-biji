## 一、完整技术链：Weather → Site → Power → Decision

成熟系统的链路不是「历史数据 → AI → 未来功率」，而是五层：

1. **未来天气会怎样**（天气预报层）：风电看风速/风向/空气密度/边界层稳定度；光伏看太阳辐射/云量/温度/湿度/气溶胶。来源 = NWP（ECMWF/GFS/WRF）+ 区域高分辨率模式 + AI 天气系统。
2. **大尺度天气 → 场站天气**（气象降尺度与订正）：地形降尺度与微地形订正、模式偏差订正与 MOS、风速垂直外推、卫星/雷达/地面观测融合、辐照分解与局地微气象修正。**复杂山地/高原/强局地环流区域，这一层可能比后面的 AI 算法更重要。**
3. **场站天气 → 功率**（物理映射）：风电 `Wind → Rotor → Mechanical → Electrical`；光伏 `Solar → PV Module → DC → Inverter → AC`。
4. **理论功率 → 真实运行功率**（运行订正）：叠加尾流、设备衰减、偏航、积灰、覆冰、检修、故障、限发、AGC 控制。
5. **预测结果 → 决策应用**（并网考核 → 调度/市场/储能/辅助服务）。

> 与 `晴川观象_物理模型工具链参考.md` 呼应：晴川给出的是第 2–4 层的具体工具链（pvlib/PVWatts/SAPM/Perez、风电轮毂换算），本文给出的是同一链路的"为什么这样分层"的认知框架。

## 二、算法谱系定位表（核心：方法选型决策依据）

不同算法**不存在"先进—落后"排序，而是承担不同功能**。选型应按"时间尺度 × 天气类型 × 地形 × 数据基础 × 业务目标"组合判断。

| 方法 | 最擅长解决的问题 | 主要局限 | 更适合的位置 |
| :--- | :--- | :--- | :--- |
| **Persistence / ARIMA** | 短时惯性、时间连续性（P(t+Δt)≈P(t)） | 难处理天气突变（冷空气/锋面/阵风/云团快速发展） | 超短期基准；评价复杂模型的对照基线 |
| **SVM / Random Forest / XGBoost / LightGBM** | 结构化表格数据中的非线性关系 P=f(X)（X=历史功率/风速/温度/辐照/NWP 偏差/设备状态） | 时空表达能力有限 | 偏差订正、残差预测；小样本稳定、可解释（SHAP/特征重要性） |
| **LSTM / GRU** | 时间依赖（历史状态对未来影响） | 若只喂历史功率而无未来气象，本质仍是复杂时间外推器 | 时序建模；需配合未来气象输入 |
| **CNN** | 空间图像特征（云团/雷达/天空成像） | 长时间序列能力有限 | 光伏云图、雷达、空间场 |
| **Transformer** | 长序列、多变量、多站点关系 | 数据/算力要求高 | 时空融合 |
| **GNN** | 多场站空间传播关系（同一天气系统自西向东） | 图结构设计复杂 | 场群预测 |
| **物理模型** | 天气→功率因果映射（P=½ρACp v³；光伏辐射→倾斜面→组件温度→DC→AC） | 难完整描述真实运行偏差 | 基础功率模型；新场站冷启动 |
| **物理 + AI（融合）** | 兼顾机理与实际偏差 | 系统复杂度更高 | **当前较成熟工程路线** |

**关键结论**：
- **Persistence 仍是极强的超短期基准**——评价任何复杂 AI 模型，先问"相比 Persistence 提高了多少？"
- 复杂模型可提取信息，**不能创造不存在的信息**：NWP 错、降尺度错、运行标签错，再复杂的 AI 也只更"漂亮"地拟合错误。

> 与 `申威睿思_功率预测平台方法论参考.md` 交叉：申威的时间尺度分段（超短期 0–4h/短期 0–72h/中期 0–14d）是本文"时间尺度×算法"判定的工程落地。

## 三、标签污染三概念解耦（数据治理核心前提）

训练数据 ≠ 自然出力数据。存在限电/故障/检修/AGC 的场站，至少须区分三个概念：

| 概念 | 含义 |
| :--- | :--- |
| **Pavailable（可用/可发功率）** | 当前气象条件下理论上能发的功率（天气驱动） |
| **Pactual（实际并网功率）** | 受调度限发/AGC/检修等约束后实际并网的功率 |
| **Pschedule（计划/调度功率）** | 申报/计划/AGC 指令给定的功率 |

**典型标签污染**：气象可发 500 MW，因调度限发实际只出 300 MW；若直接把 300 MW 当标签，模型会学到"这种天气只能发 300 MW"，下次无限制时也预测 300 MW。

**对策**：训练前必须先识别运行状态（正常/限电/故障/检修/弃风弃光/AGC/覆冰）；目标是把**天气驱动功率**与**电网控制功率**解耦——要估"自然可发功率"，须把调度约束从气象—功率关系中剥离。

> 与 `申威睿思_功率预测平台方法论参考.md` 交叉：申威的"限电识别（实发/可用/AGC 限值三者关系）"是本文三概念解耦的工程实现；本文给出的是更上层的概念框架与污染机理。

## 四、时间尺度 ↔ 信息源匹配

不同时间尺度依赖**不同信息源**，不是"换更复杂的网络"：

| 时间尺度 | 主要信息源 |
| :--- | :--- |
| 几分钟 | 当前功率、SCADA、Persistence、高频运行状态 |
| 几十分钟 | 卫星、雷达、天空成像、云移动、实时气象 |
| 几小时 | 高频 NWP、实时场站气象、时空 AI、多源融合 |
| 日前 | NWP、AI 天气模式、物理功率模型、ML 订正、多模式融合 |

正确问题不是"LSTM 还是 Transformer"，而是：在什么时间尺度、天气类型、地形、数据基础、业务目标下，哪一类信息+模型组合最合适。

## 五、评价体系升级：平均准确率 → 事件性能 + 运营价值

过去只看 RMSE/MAE/MAPE/平均准确率；但"全年平均很好、每次寒潮/大爬坡/低风持续事件都错"的模型，对电网实际价值未必高。

应补充评价：
- 爬坡事件是否识别
- 爬坡发生时间是否准确
- 极端天气下是否持续失效
- 连续误差持续多久
- 模型是否存在系统偏差
- 模型失效后能否诊断原因

**Average Accuracy → Event Performance + Operational Value**：事件性能与可诊断性，可能比平均准确率提高 0.5 个百分点更重要。

> 与 `行业标准与精度基准参考.md` 交叉：该文给出的是考核口径的 WRMSE 与国标误差上限（合规底线）；本文给出的是"评价哲学应从平均转向事件"的方法论补充。二者共同构成完整的评价体系视角。

## 六、天气底座变化（前沿索引，非落地必选）

下一代变量可能不在"下游换更复杂的 AI 模型"，而在**天气预测本身**：
- 传统 NWP：ECMWF、GFS、WRF（完整物理框架、数据同化、高分辨率动力过程）
- AI 天气模式：Pangu-Weather、GraphCast、FourCastNet、GenCast、AIFS（计算速度、大尺度模式识别、集合生成）
- 趋势：**NWP + AI Weather + Observation** 组成新气象底座，再经降尺度→物理功率→AI 订正传到出力预测。

## 七、与本项目落点建议

1. 分析思路的"方法选型"小节应直接引用第二节**算法谱系定位表**，并明确"以 Persistence 为超短期基线、以物理+AI 融合为工程主线"。
2. 数据治理小节应引用第三节**三概念解耦**，把"限电/AGC 样本须剔除或标注"作为数据清洗硬性前提（呼应申威限电识别）。
3. 评估指标小节应引用第五节，在 MAE/RMSE/MAPE/R²/WRMSE 之外，补充"事件性能（爬坡识别率、极端天气失效天数）"作为辅助评价维度。
4. 物理-数据融合的残差框架（`Residual = Pactual − Pphysical；Pforecast = Pphysical + ΔPAI`）建议作为本项目方法论主干表述（与晴川物理引擎、申威工程化互补）。
