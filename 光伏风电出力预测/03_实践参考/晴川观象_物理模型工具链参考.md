## 一、预测链路总览（物理模型法）

文章采用"气象输入 + 物理模型"直接计算逐小时功率，与本项目框架的对应关系：

| 本项目框架（论文辅助） | 本文档物理法实现 |
| :--- | :--- |
| NWP 物理边界条件 | Open-Meteo / ECMWF IFS·GFS·ICON 提供风速、辐射、温度、云量 |
| 统计/ML 纠偏 | 本文档未用 ML，走纯物理模型；可作"物理打底、ML 纠偏"中的物理基线 |
| 概率预测 | 未涉及（确定性逐时估算） |

> 落点：本项目的"分析思路"可明确区分两条技术路线——**物理模型法**（可解释、少数据依赖、适合缺历史场站）与 **ML/统计法**（精度高、需历史样本），并说明二者常组合使用。

## 二、光伏计算链路（`pvlib` + `PVWatts` + `SAPM` + `Perez`）

计算顺序（原文表述，已对齐标准光伏建模术语）：

1. **倾斜面辐照度**：依位置、时间、组件倾角与朝向，结合直射 / 散射 / 水平总辐射，估算落在组件倾斜面上的辐照度；**散射部分用 `Perez` 辐照模型**处理。
2. **组件温度**：用 **`SAPM` 组件温度模型**，依辐照、气温、风速估算组件温度（气温 ≠ 组件温度，风影响散热）。
3. **出力计算**：将有效辐照、组件温度、装机参数、温度系数输入 **`PVWatts`** 计算出力，计入标准系统损耗，并按容量上限限制输出。

链路：`气象与场站参数 → 倾斜面辐照(Perez) → 组件温度(SAPM) → PVWatts 出力 → 损耗与容量限制`

- 工具均为真实公开库/模型（可查证）：`pvlib`（Sandia 开源 Python 光伏建模库）、`PVWatts`（NREL 光伏性能模型）、`SAPM`（Sandia Array Performance Model）、`Perez`（ diffuse 辐照模型，Perez et al.）。

## 三、风电计算链路（轮毂高度换算 + 通用功率曲线）

计算顺序：

1. **轮毂高度风速换算**：优先用多个有效高度层风速，按**对数高度律插值/外推**到轮毂高度附近；仅单层可用时退化为**幂律外推**；轮毂高度资料缺失时取默认参数。
2. **通用功率曲线**：切入风速以下不出力 → 有效区间随风速上升 → 额定区间受额定功率限制 → 超切出风速按模型置零。
3. **场站损耗**：扣除场站损耗后得到估算出力。

链路：`多高度风速 → 轮毂高度换算(对数/幂律) → 通用功率曲线 → 场站损耗`

- 关键提醒：**10 m 风速 ≠ 风机轮毂高度风速**，必须做高度换算；风不是越大发电越多，取决于所处功率曲线区间。
- 注意：文章用的是"通用风机功率曲线"，**未针对实际机型逐一校准**，缺参数时取默认值。

## 五、计量口径提醒（建议在分析思路中显式声明）

文章反复强调的"数字从哪里来、哪些没算进去"，是功率预测最容易踩坑的地方，建议本项目直接吸收：

1. **10 m 风速 ≠ 轮毂高度风速**：风电估算必须先做高度换算。
2. **模型估算 ≠ 实际发电量**：未接入电站电表/SCADA 实测，页面数字为气象条件下的估算。
3. **未计入限电、检修、故障影响**：预测上限 ≠ 可上网电量。
4. **缺设备参数 → 用默认值**：通用功率曲线未逐机型校准，精度有上限。
5. **必要数据缺失 ≠ 零发电**：不应把"没数据"直接当"零出力"。
6. **"未触发预警" ≠ 发电条件良好**：预警只代表未命中监测规则。
7. **多源数据周期不一致**：电站目录 / 气象 / 卫星各有延迟与缺测，勿笼统贴"实时"标签。
