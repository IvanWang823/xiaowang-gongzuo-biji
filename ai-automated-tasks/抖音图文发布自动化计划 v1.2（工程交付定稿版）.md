# 抖音图文发布自动化计划 v1.2（工程交付定稿版）

> 版本：v1.2  
> 范围：仅图文，不含视频  
> 对象：将抖音图文系列图片上传至抖音创作者中心，填写标题和正文后交由用户手动点击发布  
> 红线①：发布按钮永留人工。AI 不点击发布，不调用发布接口，不设置定时发布。  
> 红线②：用户未确认发布成功前，不得执行 `bsk session stop`。  
> 红线③：不得连续逐张 `bsk fill` 同一 `input[type=file]`，避免覆盖，导致只剩最后一张图。  
> 本版已合并豆包终审建议：修正 request-help 文案歧义、封面校验误点风险、会话清理时序歧义，统一术语与格式。

## 三、执行命令序列

以下为从启动到交接的完整 `bsk` 命令序列。每一步标注预期行为和判断条件。

### Phase 0：启动会话

```bash
# 启动 Agent Window，捕获输出的 4 字母 session id（例如 "a7xk"）
bsk session start
# 输出示例：Session started: a7xk
# ⚠️ 记下这个 ID，后续所有命令都需要 --session <ID>
```

**记录项：**

- `SESSION_ID`
- 启动时间
- 账号标识
- 代理 / IP（如适用）

---

### Phase 1：导航至抖音创作者中心

```bash
bsk navigate "https://creator.douyin.com/creator-micro/home" --session <ID>
bsk snapshot --session <ID>
```

**预期结果：** 页面加载完成后进入创作者后台首页。

**登录校验：**

- 若快照出现登录按钮、二维码、登录表单，判定为未登录或登录过期。
- 立即执行 `bsk request-help`，提示用户先扫码登录。
- 登录成功后再继续，不得跳步。

```bash
bsk request-help --session <ID> \
  --prompt "检测到抖音创作者中心未登录，请先扫码登录。登录成功后点击 Done。" \
  --title "请先登录抖音创作者中心" \
  --timeout 5m
```

**登录校验通过后：**

- 寻找包含“发布”“创建”“图文”“上传”等关键词的元素。
- 记录目标元素的 `@eN` ref。

---

### Phase 2：进入图文发布页

```bash
bsk click @eN --session <ID>   # @eN 替换为上一步快照中发现的发布按钮 ref
bsk snapshot --session <ID>
```

**确认要点：**

- 页面出现图片上传区域（拖拽区域或“上传”按钮）。
- 页面出现标题输入框和正文/描述输入框。
- 记录文件上传 input 元素的 ref 或 selector。
- 若页面结构变化，执行 `bsk observe` 重新理解页面，或 `bsk screenshot` 视觉确认。

### Phase 3：上传 7 张图片

**策略：优先一次性设置多文件，禁止连续逐张 fill 同一 input。**

```text
优先级：
1. bsk fill 是否支持一次性多文件（逗号分隔 / 数组 / FileList）
   ├─ 支持 → 一次上传 7 张
   └─ 不支持 → 进入 2
2. bsk evaluate 能否通过 CDP 注入 FileList
   ├─ 支持 → 注入 7 文件
   └─ 不支持 → 进入 3
3. bsk request-help 让用户在文件选择对话框中一次多选 7 张
```

**上传文件清单：**

```text

F:/社媒运营/抖音图文发布自动化方案/dy-02-overview.png
```

```bash
bsk request-help --session <ID> \
  --prompt "请在此弹出的文件选择对话框中，一次多选以下 7 张图片：\n1. dy-01-cover.png（封面）\n2. dy-02-overview.png（总览）\n3. dy-03-auto-part1.png（A0-A4）\n4. dy-04-auto-part2.png（A5-A8）\n5. dy-05-manual.png（B1-B4）\n6. dy-06-redline.png（红线）\n7. dy-07-handover.png（交接）\n\n文件路径：F:/社媒运营/抖音图文发布自动化方案/" \
```

> `request-help --target` 仅用于高亮/定位，不得触发自动点击。

**上传后验证：**

```bash

```

**确认要点：**

- 图片列表/缩略图区域显示 7 张图片。
- 每张图有缩略图和序号。
- 第一张图（cover）默认即为封面。
- 若缩略图少于 7，判定上传失败，走 fallback。

**超时分支：**

- `request-help` 超时后，**不得执行 `bsk session stop`**。
- 保留会话，发告警，等待人工处理。
- 记录状态为“待人工发布超时”。

### Phase 11：会话清理

```bash
# 仅当用户确认发布成功，并且发布记录回写全部完成之后，才允许执行会话停止操作。
bsk session stop <ID>
```

**会话停止条件：**

- 用户确认发布成功
- 发布记录回写全部完成
- 无待处理异常

**以下情况不得执行 `bsk session stop`：**

- `request-help` 超时
- 用户未确认发布
- 处于失败、待人工、中断状态
- 草稿尚未保存

> 失败、待人工、超时、人工中断时，停止会话会关闭页面并导致草稿丢失。

## 四、错误处理与 Fallback 策略

### 4.1 常见异常场景

| 场景 | 检测方法 | 处理策略 |
|------|----------|----------|
| 页面未登录 / 登录过期 | 快照出现登录按钮或二维码 | `bsk request-help` 提示用户先登录 |
| 文件上传失败（fill 不支持 file input） | `bsk fill` 返回非零退出码或错误提示 | 切换到 `request-help` 让用户手动多选 |
| 单次只能上传 1 张图 | 第二次 fill 覆盖第一次 | 改为一次性多文件或 `request-help` |
| 标题超长 | 快照显示字数超限提示 | 缩短标题后重新 fill |
| 图片上传超时 | 命令返回超时错误 | 增加 `--timeout` 参数或分批上传 |
| 页面结构变化（DOM 改版） | 快照中找不到预期元素 | `bsk observe` 重新理解页面，或 `bsk screenshot` 视觉确认 |
| 网络错误 | 命令返回协议/传输错误 | `bsk doctor`（会话诊断）诊断后重试 |
| 话题无法自动选择 | 输入 # 后无下拉或选择失败 | `request-help` 让用户手动添加 |
| 终验拦截 | 违禁词、外链、二维码、联系方式 | 低风险自动替换，高风险转人工 |
| 重复任务 | `task_id` / sha256 重复 | 幂等去重，不重复上传 |

### 4.2 重试规则

- 同一操作最多重试 **2 次**。
- 第 2 次仍失败则切换 fallback 方案或 `bsk request-help`。
- 绝不无限循环重试。
- 重试必须记录变更日志。

### 4.3 文件上传决策树

```text
bsk fill 能否一次性设置多文件？
├─ YES → 一次上传 7 张
└─ NO → bsk evaluate 能否通过 CDP 注入 FileList？
    ├─ YES → 注入 7 文件
    └─ NO → bsk request-help 让用户在文件对话框中一次多选 7 张

禁止：连续逐张 fill 同一 input，避免覆盖。
```

## 五、注意事项

1. **绝对不点击发布按钮**：红线，必须通过 `bsk request-help` 移交给用户。
2. **Session 停止条件**：仅用户确认发布成功后，才允许按守护进程策略停止会话。失败、待人工、超时、人工中断时，不得执行 `bsk session stop`，否则会关闭页面并导致草稿丢失。
3. **Ref 失效**：每次 DOM 变化（导航、上传、填写）后必须重新 `bsk snapshot` 获取新 ref。
4. **Windows 路径**：统一用正斜杠 `/`，或双反斜杠 `\\`。
5. **等待时间**：图片上传可能较慢，必要时加 `bsk wait-ms 3s` 等待。
6. **用户登录态**：确保用户的 Chrome 已登录抖音创作者平台。
7. **话题标签**：必须通过 `#` 下拉选择，不能只填纯文本。
8. **`request-help --target`**：仅用于高亮/定位，不得触发自动点击。
9. **退出码**：以 bsk 官方文档为准，不写死未经核实的退出码。
10. **`--session` 语法**：全文统一，核对 CLI 是否支持。
11. **`\n` 换行**：bash 双引号内 `\n` 不会自动解析为换行；如需换行，优先使用字面换行，bash 环境可使用 `$'...'` 语法。
12. **`bsk fill` 长文本**：可能不触发 React/Vue `onChange`，填完后读 `innerText` 校验，必要时逐字输入。
13. **文案合规**：避免焦虑营销、违规话术；发布按钮必须人工确认。
14. **封面切换**：默认不主动执行封面切换操作；如需更换封面，需显式点击“设为封面”按钮，并记录变更日志。

## 六、监控、告警、审计

| 指标 | 说明 |
|---|---|
| 上传成功率 | 单图/整任务 |
| 单图失败率 | 按原因分类 |
| 图片规格校验通过率 | 数量、格式、大小、比例 |
| 草稿保存率 | 填写完成 |
| 终验拦截率 | 违禁词/外链/话题 |
| 自动替换数 | 文本、话题 |
| 人工发布率 | 应为 100% |
| 发布成功率 | 用户确认发布 |
| 回写成功率 | `note_id`/URL |
| 会话异常停止次数 | 应为 0 |

**告警渠道：** 飞书/钉钉。  
**告警分级：** P0 冻结、P1 失败、P2 提醒。

## 七、验收用例

- 正常 7 张图片上传。
- 仅上传 1 张图片。
- 图片数量不足 7 张。
- 比例不满足抖音规范。
- 图片短边尺寸不足。
- 单图超大小限制。
- 重复图。
- 含二维码。
- 标题超长。
- 正文外链。
- 话题标签无法选择。
- 未登录。
- 登录过期。
- 上传超时。
- 页面结构变化。
- 网络错误。
- 重复任务。
- `request-help` 超时。
- 用户未确认发布。
- 人工中断。

## 九、执行顺序总览（速查表）

```text
Step 0:  bsk session start                          → 记录 SESSION_ID
Step 1:  bsk navigate https://creator.douyin.com/... → 进入创作者中心
Step 2:  bsk snapshot                                → 登录校验
Step 3:  未登录 → bsk request-help                   → 用户扫码登录
Step 4:  bsk click @publish-entry                    → 进入图文发布页
Step 5:  bsk snapshot                                → 确认编辑器加载
Step 6:  [上传 7 张图片]                             → 一次性多文件 / evaluate / request-help
Step 7:  bsk snapshot                                → 确认图片上传成功
Step 8:  [图片规格校验]                              → 数量、格式、大小、比例、封面
Step 9:  [校验第一张缩略图为封面（不执行点击）]       → 仅校验，不切换封面
Step 10: bsk fill @title-input                       → 填写标题
Step 11: bsk fill @description-textarea              → 填写正文
Step 12: [添加话题标签]                              → # 下拉选择 / request-help
Step 13: bsk snapshot                                → 发布前终验
Step 14: bsk request-help                            → ★ 移交给用户点击发布 ★
Step 15: [发布后回写]                                → note_id / URL / 截图 / 状态
Step 16: bsk session stop <ID>                       → 仅发布成功后清理会话
```

## 十二、开放问题

- 抖音图文标题、正文、话题的具体限制需按最新规则配置化。
- 图片数量、格式、大小、比例、短边限制需按抖音页面实时提示配置化。
- 话题自动选择是否稳定，需实测；不稳定则默认走 `request-help`。
- `bsk` 是否支持一次性多文件上传，需核对官方文档。
- `bsk` 退出码定义需核对官方文档。
- `request-help` 超时后的浏览器守护进程保活策略需与运维确认。
- 发布后数据抓取范围需另行确认。
