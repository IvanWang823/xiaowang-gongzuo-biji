## 2. 阶段详解

### P1 · 资产盘点与格式解析

| 项 | 内容 |
| --- | --- |
| 目标 | 搞清 9 个文件各是什么、彼此什么关系 |
| 动作 | `Glob` 列全量 → 精读 2 份 md 报告 → 逐个 Excel 列表结构 → 解析二进制 wps |
| 工具 | Glob / Read / openpyxl / olefile |
| 产出 | 一条清晰的「5 迭代版本 + 3 产出报告 + 1 规则源文件」的版本脉络 |
| 卡点 | ① 子代理读不了非系统盘 ② `.wps` 是二进制 |

**关键判断**：这 9 个文件不是 9 份独立资料，而是**同一条数据链的不同阶段快照**。识别出这一点，后面的「归类」和「只留最终版」才成立。

### P2 · 数据核验与口径确立

| 项 | 内容 |
| --- | --- |
| 目标 | 确认哪份数据可信、用什么口径统计 |
| 动作 | 对主表 74 条逐行实算面积/成交价/单价/周期 → 与两份已有报告的每一个数字对照 |
| 产出 | 8 项指标逐条对照表，标出「不符 / 部分不符」 |
| 结论 | **既有报告的具体数字全部不可引用**，本报表所有数字改为逐行实算 |

**确立的统计口径**（此后所有产出统一遵守）：

| 统计类型 | 口径 | 理由 |
| --- | --- | --- |
| 结构分布（区域/装修/楼层/面积段/周期分档） | 全部 **74** 条 | 9 条收房虽无价，但房源结构上是有效样本 |
| 均价 / 成交价 / 单价 / 周期 | **65** 条有价成交 | 收房无成交价，计入会拉低均值 |
| 报告呈现 | 条形长度与右侧数值用 74 口径，副标签均价用 65 口径并显式注明 | 避免两类数字互相打架 |

### P3 · 首版交付

静态 HTML 报表（手写 SVG 图表 + 原生 JS 搜索/筛选/排序）+ 整理版 Excel（4 sheet）。核心约束：**单文件、零外部依赖、断网可看**。

### P4 · 文件夹物理归置

| 步骤 | 动作 | 校验 |
| --- | --- | --- |
| 1 | 整份备份到工作区 `.workbuddy\backup\房产数据_20260910\` | 9/9 文件字节数一致 |
| 2 | 建 `01_主数据` ~ `05_整理产出` 五目录 | — |
| 3 | 分 3 批移动（每批 ≤3 个文件，确认后再下一批） | 每批 `mv -v` 输出核对 |
| 4 | 拷入产出 + 写 README.md | — |
| 5 | 逐文件 `stat -c%s` 与备份比对 | 9/9 完全一致 |

**决策依据**：文件名一律保持原样。版本信息就藏在文件名里（「修正楼层版」「补全小区名+修正楼层版」），改名反而丢线索 —— 只靠目录分层。

### P5 · 设计改版与口径统一

用户提供了一套新视觉设计（浅灰底 + 径向渐变 + 卡片投影 + sticky 导航 + 克莱因蓝体系）。做法是**保留其 CSS/JS 设计层，正文数据全部重新生成**。

核对发现该设计版存在**口径混用**：图表计数用 74 口径（正确），但正文百分比沿用 65 口径，导致「条形画 46 套、正文写 39 套」这类自相矛盾。同步修正 5 处，并把面积段标签由「61-80㎡」改为左开右闭的「60–80㎡」（原写法会把 60.06㎡ 那条分错桶）。

### P6 · 版式微调

用户截图反馈：排行榜 4.1 / 4.2 两表并排时列宽被压到 40px，「精装」「25.0万」「10天」全被折成两行。

**改法**：删除并排容器，三张表改为独占整行上下堆叠。
**防回归**：新增 `tbody td.num{white-space:nowrap}` 与 `table.rk tbody td{white-space:nowrap}`，同时用 `table.rk tbody td:nth-child(2){white-space:normal}` 放行小区名长字段。
**注意**：**不能**给所有 `tbody td` 加 nowrap —— 第 1/5/6 节的「说明 / 备注 / 边界定义」长文本列会横向溢出。

### P7 · 外部调研

按贴合度调研 GitHub 同题材项目。**4 个候选里 1 个是 404**（用户转述的信息源不可靠），逐个 WebFetch 核实后才给结论。

**核心判断**：鲅鱼圈数据缺「时间序列」和「经纬度」两样东西 —— 任何走势图 / 地图方案都必须先补数据，不是换代码模板能解决的。

### P8 · 交互看板

内联 Chart.js 4.4.4（不挂 CDN，保证离线可用），实现 4 个联动筛选（区域 / 装修 / 楼层类型 / 面积段）+ 6 张 KPI 卡 + 7 张图 + 联动明细表。

在准备数据集时又做了一次两表交叉验证，**发现「区域划分」列 5 处冲突**（详见第 4 节）。

### P9 · 定稿与交付物净化

| 项 | 内容 |
| --- | --- |
| 目标 | 交付物「能看」→「能交付」 |
| 动作 | 复核 3 个 HTML → 正则剥离 `data-page-node-id` → 补打印样式 / 进度条 / 返回顶部 / 导航高亮 → 双份逐字节同步 |
| 产出 | 洁净交付物 ×3 + 本报告定稿 |
| 卡点 | 预览器静默回写，注入 1,872 / 493 处属性，肉眼不可见 |

**为什么必须做**：这类属性是预览器为实现「点选元素」而加的，对渲染毫无影响 —— 正因为没影响，所以不会被任何视觉检查发现，但会跟着文件一起交付出去，并且让体积近乎翻倍（静态报表 77 KB → 159 KB）。

**同时补齐的**：`@media print` 打印 / 存 PDF 样式（此前打印会出现导航栏、卡片投影、背景色丢失），以及阅读辅助 —— 顶部阅读进度条、右下角返回顶部、导航栏当前小节高亮。

## 3. 踩坑与解法

> 这一节是本次工作中最可复用的部分 —— 11 个坑（10 条本次实测 + 1 条历史经验复用），每个都记了「表现」和「解法」。

| # | 坑 | 表现 | 解法 |
| --- | --- | --- | --- |
| 1 | 读 Excel 的子代理**不支持非系统盘** | `F:\` / `F:/` / `/F:/` 三种写法全部失败（`INVALID_LOCAL_PATH`） | 非 C 盘的 xlsx **直接用 openpyxl 读**（venv 路径见附录） |
| 2 | `.wps` 是 **OLE2 二进制** | 当文本读全是乱码 | `olefile` 打开 → 读 `WordDocument` 流 → `utf-16le` 解码 → 正则捞中文 |
| 3 | **Chart.js 内联后页面数据全空** | CSS 完全正常，KPI 和图表全空白 —— 极易误判成渲染问题 | jsDelivr 的 UMD 文件以多行注释块开头，按行截断只剩孤立 `*/` → 整段 script 语法错误。改为按 `*/` 定位切割：`raw[raw.index('*/')+2:]` |
| 4 | 多版本数据文件的**标注冲突** | 两张主表 5 条记录区域不一致，不知信哪个 | 做**内部一致性检查**：同一实体（小区）是否被拆到多个类目。自相矛盾的那份出局（详见第 4 节） |
| 5 | **统计口径混用** | 图表画 46 套、正文写 39 套，同一段话自己打自己 | 口径写进图注与脚注，且生成脚本里两个口径分别命名（`N` / `NS`），杜绝手写 |
| 6 | CSS `nowrap` **加得太宽** | 排行表不折行了，但说明/备注长文本列横向溢出 | 收窄作用域：用具体类（`td.num` / `table.rk`）替代 `tbody td`，再对个别列 `white-space:normal` 放行 |
| 7 | Chrome 无头截图**截的是视口** | `--screenshot` + `#anchor` 定位不到目标区块（smooth scroll 干扰） | 生成临时 HTML，在 `</style>` 前插 `display:none` 隐藏无关 section；中文路径需 percent-encode |
| 8 | **用户转述的仓库名不可靠** | 4 个候选里 1 个是 404 | 任何外部资源（仓库/链接/数据）先核实存在性，再谈内容 |
| 9 | GitHub 搜索 API **未登录限流** | 连续查询后返回 403 | 限流 10 次/分钟，超了读 `X-RateLimit-Reset` 等重置；查询间 `sleep 4` |
| 10 | 大 HTML 内联 JSON 块**不能用 `JSON.parse` 整块** | （历史经验，本次规避） | 改用纯字符串 `replace` + 唯一上下文锚定 |
| 11 | **预览器回写污染交付物** | 在编辑器里打开 HTML 预览后文件被回写，注入 `data-page-node-id` 属性 —— 静态报表 1,872 处、看板 493 处，体积近乎翻倍（77 KB → 159 KB）。**渲染完全正常，肉眼看不出来** | 交付前统一剥离该属性，只留洁净副本；并把「交付物洁净度」列为定稿阶段必做项 |

### ⚠️ 1. 既有分析报告的数字整体不可信

`鲅鱼圈房产数据全维度分析报告（每栏解读+隐藏关系挖掘）.md` 的均价、极值、区间**全部与源表对不上**：

| 指标 | 报告值 | 源表实算 | 差异 |
| --- | --- | --- | --- |
| 平均单价 | 7,620 元/㎡ | **2,992 元/㎡** | 差 1.5 倍 |
| 单价区间 | 2,546 – 11,803 | **566 – 6,910** | — |
| 成交价区间 | 16.8 – 188.0 万 | **3.8 – 68.8 万** | — |
| 面积区间 | 40 – 185 ㎡ | **37 – 180 ㎡** | — |

| 南城区均价 | 8,230 元/㎡ | **3,858 元/㎡** | — |

**处理**：该报告定性方向部分仍成立，但**所有具体数字不可引用**，已写入 README 警示。

### ⚠️ 2. 两张主数据表「区域划分」列冲突（本次新发现）

逐字段交叉验证 `最终版本.xlsx` 与 `最终版本+仪表盘+报表.xlsx`：**小区 / 楼层 / 面积 / 装修 / 成交价 / 单价 / 周期 七项完全一致，只有「区域划分」列 5 处矛盾**。

判定用的是**内部一致性检查**：

| 小区 | `最终版本.xlsx` | 成品表 | 判定 |
| --- | --- | --- | --- |
| 宋屯新区 G 区 | 编码 38 记北城 / 编码 53 记南城 | 均北城区 | A 自相矛盾 |
| 红旺集团大厦 B 区 | 编码 25 记北城 / 17·28·60 记南城 | 均北城区 | A 自相矛盾 |

**结论**：同一个小区不可能同时属于两个城区 —— `最终版本.xlsx` 内部自相矛盾，**成品表内部零跨区**，故采用成品表口径（北城 46 / 南城 23）。此前的交付数字无误。

### ⚠️ 3. 成品表「报表」页跨行错位

区域前五房源表中成交价与单价串行。例如渤海钰珠 99㎡：真实成交价 43.98 万，报表页显示 12.7 万却保留 4,442 的单价 —— **两列互相矛盾**。未修复（属源文件本身缺陷）。

### ⚠️ 4. 9 条低价离群记录

## 5. 方法论沉淀

从这次工作里抽出的 7 条通用做法，适用于任何「多版本数据文件夹 → 可视化交付」的场景：

**① 先做内部一致性检查，再谈数字对不对**
多版本文件夹里，判断哪份可信的最强手段不是「哪份更新」，而是**看哪份自相矛盾**。同一实体（小区/城市/门店）被拆到多个类目 = 该文件有标注错误。这一条直接决定了本次 46/23 的成立。

**② 统计口径必须显式声明，且以编程方式绑定**
口径不能靠人记。生成脚本里给两个口径分别命名（`N` = 全量、`NS` = 有价），正文里所有数字都用变量而不是手写。手写就会出现「图 46 篇 39」这种错误。

**③ 所有数字逐行实算，不引用二手报告**
既有报告只用来做交叉核对，绝不用来取数。本次正是靠逐行实算才发现报告整体失真。

**④ 移动用户文件 = 备份 + 分批 + 字节级校验**
顺序固定：整份备份 → 逐文件比对 → 建目录 → 分批移动（每批 ≤3 个）→ 移动后再比对一次。全程只移动，不删除、不改名、不覆盖。

**⑤ 视觉问题用无头截图验证，不靠猜**
CSS 改动后必须实际渲染确认。临时视图 + 无头截图的组合，可以在几秒内定位到任意区块。

**⑥ 外部资源先验真再评估**
仓库名、链接、数据来源，先核实存在性。本次 4 个候选里就有 1 个是 404。

**⑦ 交付前必做洁净度与体积复核**
文件「能打开、能看」不等于「能交付」。任何在编辑器 / 预览器里打开过的 HTML，都要在定稿前查一遍是否被回写注入了属性、体积是否异常膨胀 —— 这类污染静默发生，肉眼看不出来，但会跟着交付物一起发出去。
