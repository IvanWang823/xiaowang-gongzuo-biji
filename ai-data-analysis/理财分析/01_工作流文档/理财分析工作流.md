## 路径与环境变量（跨设备 · 必读）

脚本**不再硬编码盘符**，靠环境变量适配不同设备：

```python
import os
BASE_PATH = os.getenv("FINANCE_PATH", "F:/理财分析")   # 默认 Windows 路径
OUT_FILE  = os.path.join(BASE_PATH, "04_成果", "四平台理财持仓分析.xlsx")
```

- **本地 Windows**：直接跑，脚本位于 `{BASE_PATH}/03_脚本/gen_analysis.py`，生成的 xlsx 落到 `{BASE_PATH}/04_成果/四平台理财持仓分析.xlsx`
- **云端 / macOS / Linux**：先 `export FINANCE_PATH=/your/path`（或设系统环境变量），脚本自动适配
- ⚠️ **所有文件路径必须用 `os.path.join(BASE_PATH, ...)，禁止再出现 `F:/...` 字面量**（否则换设备即报错）
- **配套脚本获取**：`gen_analysis.py` 与本工作流一同提供，存放于 `{BASE_PATH}/03_脚本/gen_analysis.py`（数据硬编码在 `rows` 列表，改数据重跑即可）。原始持仓截图存于 `{BASE_PATH}/05_原始截图/`。请确保使用最新版本（含 §3 币种铁律与 §5 推演）。

## 0. 角色定位与红线（最高优先级）

| 模式 | 触发条件 | 做什么 | 不做什么 |
|---|---|---|---|
| **纯客观版（默认初始模式）** | 用户没明确授权做诊断/建议 | 数据整理、图表、汇总、数学推演 | 不给任何"该买/该卖/该调"的结论 |
| **分析师版（投资侧诊断）** | 用户明确说"按分析师/诊断版"或选了对应选项 | 在客观版基础上 + 整体诊断 + 优化思路 + 优先关注清单 | 只给逻辑方向，**不指定具体产品、不替用户下决定** |
| **个人财务分析师（全量版）** | 用户提供「个人财务分析师 AI」prompt 或要求全量财务画像；**2026-08-28 用户已授权"优化建议可以做"** | 在投资侧基础上扩展至收入/支出/消费/储蓄/负债/现金流/资产负债结构全链路；按 §9 固定 7 段结构输出，含优化建议 | 不预测市场、不编造数据、不迎合偏好、不替用户下决定；只给逻辑方向与方案比较 |

- 无论哪种模式，结尾都标注：**"本分析仅供参考，不构成具体投资建议"**。
- 用户偏好（记在 memory）：理财只看客观数据，不要投资建议。**但 2026-08-28 用户明确授权"优化建议你可以做"**——在「理财分析师」工作流场景下，可做优化思路/建议（仅逻辑方向与方案比较，不指定买卖），仍须全程守护栏（见 §0 表格与 §9.3）。纯客观仍是默认初始模式，用户未提"财务分析师/诊断"时自动走客观版。
- 汇率/敞口推演必须注明：**降敞口 = 对称放弃上行收益**，不是"稳赚"。

## 1. 数据流：从截图到结构化

```
用户截图/导出文件
   ↓  AI Read 读图提取（不依赖任何银行连接器，全部 disconnected）
逐张提取字段 → 口述补全缺失项（如参考年化、产品全名）
   ↓
openpyxl 脚本整体生成 xlsx（每个平台 1 个 sheet + 全行合并 + 专题 sheet）
   ↓
present_files 交付：将生成的 xlsx 通过对话内的文件卡片直接发送给用户（或提供可打开的预览/下载链接，视平台能力），用户预览核对
```

**为什么用 openpyxl 整体生成，不用编辑器实时补列：**
实战踩过坑——`editor_sdk` 逐格拼 CSV 列数易错、`add_chart` 的 `data_range` 格式不明，半天修不好。
结论：**确定性重建一律用 openpyxl 重写脚本重跑**，稳且可版本追溯（数据硬编码在 `gen_analysis.py`）。

### 1.5 异常处理机制（v2.0 新增）

截图永远比想象中更容易出问题。遇到以下情况**绝不猜、绝不脑补**：

| 异常场景 | 处理动作 |
|---|---|
| 截图模糊 / 某字段无法识别 | 该字段标 `N/A`，不动 |
| 缺"参考年化" | 标 `年化N/A`，并在汇总 sheet 顶部生成**「待补充字段清单」**列明缺什么、来自哪个平台 |
| **无法识别币种** | **暂按人民币记录并高亮标黄，同时在单元格备注"币种待核"**；交付时口头提醒用户**重点核对**该项（宁可错黄、不可错估 7 倍） |
| 某平台只截了部分（如只有基金没理财） | 注明"该平台仅含 X 类，Y 类未提供"，不强行补全 |
| 所有银行连接器 disconnected | 明确告知：无法自动拉行情，数据源只能靠用户截图/导出 |

**核心原则：宁可标注缺失，不可幻觉补全。** 所有"口述补全"项必须来自用户，AI 不编造任何数字。

## 2. 提取字段规范（防错清单）

每张截图提取时，**逐项确认**，不要想当然：

| 字段 | 必提 | 防坑点 |
|---|---|---|
| 产品全称 | ✅ | APP 显示名常截断，让用户补全名 |
| 发行方 | ✅ | 招银/中银/贝莱德建信等 |
| **币种** | ✅✅✅ | **银行"参考市值"默认显示该产品的计价币种（美元/人民币都可能）。中行那 5 只是美元，误当人民币会低估 7 倍！提取时必须看币种列。** 拿不准一律按 §1.5 标黄待核 |
| 参考市值 | ✅ | 美元产品记 USD，折人民币另算 |
| 最新收益 / 持仓收益 | ✅ | 红字=正，区分"当日"与"累计" |
| 到期日 / 赎回状态 | ✅ | 封闭/开放/持有期，影响流动性分析 |
| 类型 | ✅ | 封闭/开放/货币/债基/QDII/指数 |
| **数据日期/时间** | ✅ | 每项数据须绑定截图/导出日期；禁止跨期混算（今日人民币+三月前美元+昨日汇率=假精确）；多源数据取各自日期 |

**参考年化口径必须分开标**（用户在 APP 口述或截详情页给）：
- `近1年` 参考年化（如招行多宝月月宝 1.95%）
- `成立以来` 年化（如交银 6.24%）——可能跨好几年，**不可与近1年口径横向直接比**
- 写入单元格时连口径一起写，如 `2.36%（成立以来）`
- 用户提供前默认 `年化N/A`，触发 §1.5 的待补充清单

**实际累计收益率 = 持仓收益 ÷ 持仓金额**，脚本实时算，红字标正收益。基金区第 6 列"收益率"本来就这含义，不用重复加列。

## 2.5 重复数据检测（v2.5 新增）

多平台 / 多批次 / 补传截图时，AI 须主动识别潜在重复资产，避免同一笔钱算两遍：

- **判定规则**：同账户 + 同金额（±容差） + 同日期 + 同产品 → 优先判定为**潜在重复项**，**不自动累计**，先询问用户确认去重。
- **典型场景**：①银行截图 + 支付宝截图 + 一张「总资产汇总」截图，汇总项与各平台明细极可能重叠；②用户补传历史截图，新旧口径交叉。
- **动作**：发现疑似重复，在「待补充字段清单」旁单列「疑似重复项」并标注来源平台，请用户确认后再汇总。

## 3. 分析维度（推荐 sheet 模板）

按这 9 类模板组织（平台明细按 4 个平台各 1 个 sheet，实际生成 10 个物理 sheet），已验证完整。**各版本必选 / 可选范围（避免纯客观版越界做推演）**：

- **基础版（纯客观）· 必选**：① 各平台持仓明细（中行/招行/建行/支付宝）、② 汇总分析、③ 汇率形势分析、⑤ 全行合并总览
- **基础版 · 可选 / 按需**：④ 宏观速览（建议用户问及"为何波动"时补）、⑦ 美元敞口压力测试（属推演类，纯客观版可不做）
- **分析师版 · 额外必选**：⑥ 理财师诊断分析（整体诊断 + 优化思路，已授权）
- **全量版**：在分析师版基础上，按 §9 数据补齐情况扩展「现金流分析」「消费分析」等 Sheet

> 以下编号为**模板类别序**（1=平台明细大类，2~7=专题），**非文件物理 sheet 序**；真实物理 sheet 顺序见已生成的 xlsx（共 10 个，物理顺序：中行 → 汇总 → 汇率 → 招行 → 建行 → 支付宝 → 宏观速览 → 全行合并 → 诊断 → 压力测试）。

1. **[平台]持仓明细**（中行/招行/建行/支付宝各 1 个）
   - 基金区：名称/代码/市值/日收益/持仓收益/收益率/类型
   - 理财区：名称/金额/收益/到期状态/参考年化(标口径)/实际累计收益率
2. **汇总分析**：总览 + 按发行方 + 按类型 + 客观观察（只摆事实，不评价好坏）
3. **汇率形势分析**：实时抓 USD/CNY 即期、央行中间价、一年前对比、美元指数、美联储利率/降息预期；汇率情景测算
4. **宏观速览（v2.0 新增 · 可选）**：A/H 股主要指数涨跌、10Y 国债收益率（影响债基净值）、重大宏观事件。
   - **用途定位：仅解释"收益波动来源"，不预测、不归因到具体买卖。** 例：持仓里有港股通互联网 ETF(-31%)、债基，用户问"为什么跌"时，用当日恒生科技/沪深300/10Y 国债数据做客观归因，而非猜未来。
   - 数据用 `WebSearch` 现抓（"沪深300 今日"、"恒生科技指数"、"10年期国债收益率"），不依赖训练数据。
   - 与汇率分析并列，不替代；纯客观版也可做（只归因、不给方向）。
5. **全行合并总览**：各平台市值/收益并排 + 合计
   - ⚠️ **币种汇总铁律**：美元产品的"参考市值"以 USD 存储，**汇总行必须拆为「人民币合计」与「美元合计（原币）」两行，永远禁止把不同币种的市值列直接 SUM**。脚本层面已用 `total_mv_usd` 与 `total_mv_cny` 分离计算；未来扩展任何平台都必须遵守此约定，否则会出现"把 5.3 万美元当 5.3 万人民币"的 7 倍事故。
6. **理财师诊断分析（分析师版 · 需授权）**：整体诊断结论 → 大类资产配置表 → 6 维度分析 → 优化思路(逻辑方向) → 优先关注清单(按重要性排序) → 合规声明
7. **美元敞口压力测试**：情景价值表 + 降敞口对冲效果表

**汇率 / 宏观数据获取**：用 `WebSearch` 现抓，不依赖过期训练数据。

## 4. 关键技术决策

- **整体生成 > 实时补列**：见 §1。
- **数据硬编码进 `gen_analysis.py`**：`rows = [...]` 列表放各平台产品，更新只改这里重跑，不碰 Excel。
- **图表用 openpyxl 原生**：市值饼图、持仓收益柱状图，`save` 后不丢。
- **多平台扩展**：新增平台 = 加一个 `xxx = [...]` 数据块 + 新建 sheet 代码 + 在全行合并 `merge` 列表加一列（注意 §3 币种铁律，美元平台须单独核算）。
- **币种统一口径**：美元产品折人民币统一用一个即期（如 6.7225），变量 `rate_now` 集中定义，全文件复用。
- **路径变量化（v2.0）**：见开头「路径与环境变量」，所有文件路径走 `os.path.join(BASE_PATH, ...)`，不再出现盘符字面量。

## 5. 汇率情景推演公式（可抄）

**变量定义（先明确再套用）**：
- `USD` = 当前美元敞口本金（原币，如 53,147 USD）
- `R0` = 当前即期汇率（如 6.7225）
- `R_weak` = 弱情景假设汇率（美元走弱，如 6.5500）
- `R_strong` = 强情景假设汇率（美元走强，如 6.8500）
- `T%` = 目标美元敞口占比（如降到 50% / 40%）
- `A_total` = 全行总资产（人民币等值）

```
折人民币(情景) = 美元本金 × 假设汇率
较当前变动     = 折人民币(情景) − 美元本金 × 当前即期

# 降敞口对冲效果（假设把等值美元赎回转人民币资产，无损转换）
转出敞口(人民币等值) = USD × R0 − A_total × T%
弱情景少亏 = 转出敞口 × (R0 − R_weak) / R0
强情景少赚 = 转出敞口 × (R_strong − R0) / R0   # 取正值为"放弃的潜在收益"
```

**读数要点**：降敞口在"弱情景"列是**绿色保护**（少亏），在"强情景"列是**灰色代价**（少赚），二者数值对称。推演不含赎回费/在途/再投资收益。

## 8. AI 沟通规范（针对截图对话 · v2.0 新增）

为保证多轮截图对话不出错、且符合红线复位要求，AI 在截图类任务中**必须**遵守：

1. **收到截图第一句回复（动态判断，不硬切模式）**：
   > "已收到您的持仓截图。我的默认模式为纯客观整理，仅做数据梳理、不含买卖建议；若您希望获得诊断结论或优化建议，请直接告知，我将按分析师版 / 全量版展开。"
   > 说明：用户可能一开始就明确要求"诊断版 / 全量版"，此时不必生硬回"我是客观版"再让用户多切换一次；按用户实际意图直接进入对应模式，但**纯客观仍是默认基线**——用户未指定模式时自动走客观版。

2. **每提取完一个平台，必须口述复述并待确认**：
   > "【平台名】提取完毕：共 N 只，总市值 X 元（币种：USD/CNY），净收益 ±Y。确认无误我解析下一个？"
   > 目的：防止全篇提取完才发现币种/金额整体错（中行那次就吃过 7 倍低估的亏）。

   **多平台批量提交时的执行策略（v2.1 修订 · 防流程拖沓）**：
   若用户**一次性甩来多个平台截图**（如 4 张银行 + 9 张支付宝），AI 不应提取完第 1 张就停下等确认（用户可能在忙、回复慢，会卡死批量节奏）。正确打法：
   - ⚠️ **上下文容量提醒**：若截图**数量超过 5 张**，建议**分两批处理**（每批 ≤5 张），避免一次性 OCR 暂存数据撑爆对话上下文；每批复述完毕、用户确认后再进行下一批。
   - **内部先一气 OCR 提取全部平台数据并暂存**（不写盘、不生成最终文件）；
   - **按平台逐个输出复述结果**（沿用上面的话术格式，但句尾改为"继续解析下一个"而非"等你确认"）；
   - **全部平台复述完毕后，末尾统一询问**：
     > "以上 N 个平台数据已逐条列出，请逐一核对。有误请直接指出哪个平台哪项数；全部无误请回'确认'，我即生成 Excel。"
     > **若您附加了修改意见**（如"中行那笔收益改一下"），我会先按您的指正更新数据，**再重新列出修改后的平台摘要**，待您二次确认无误后，再生成最终 Excel。
   - 目的：既保住"逐平台复述核对"的防错价值，又避免"每平台等一次回复"造成的中断拖沓，兼顾准确率与吞吐效率；同时堵住"确认+附带修改"的衔接缝隙。

3. **用户给参考年化/全名等补全项**：原样记录、标注口径，不替用户"四舍五入"或"估算"。

4. **币种拿不准时**：主动标黄 + 口头提醒"这块币种我按人民币暂估，你核对下"，不静默假设。

5. **分析师版结束后**：主动提示"已回到纯客观默认模式"，完成红线复位。

## 9. 个人财务分析师（全量版）· 超集对接

### 9.1 数据覆盖矩阵（决定能跑哪几段）

| 模块 | 当前数据覆盖 | 状态 |

### 9.2 固定输出结构（7 段，按用户 prompt 原文）

1. **财务概况**：总结最重要数据（基于现有持仓先给投资侧概况）
2. **现金流分析**：收入/支出/储蓄/现金流健康度 —— *待补收入支出*

5. **风险提示**：最值得关注的财务风险（投资侧已识别：美元占67%集中、到期潮、单只亏损源）
6. **优化建议**：具体可执行（**2026-08-28 已授权**，仅逻辑方向与方案比较，不指定买卖）
7. **下一步行动**：1~3 件最值得做的事

### 9.3 护栏红线（来自用户 prompt，优先级等同 §0）

- 不推销金融产品、不靠预测市场制造焦虑
- 先分析现金流，再分析投资
- 优先财务安全，非单纯收益
- 区分必要/改善/冲动消费；区分事实/计算结果/假设/建议
- **数据不足明说缺什么，禁止编造**
- 不把收益预测说成确定结果
- 不迎合用户偏好
- 发现明显问题**直接指出**
- 重大财务决策给不同方案，比较风险/收益/流动性/机会成本
- 涉及实时市场数据**先 WebSearch 现抓**，不依赖过时数据
- 单笔消费记录**不立刻批评**，先结合收入/预算/历史现金流判断是否合理；缺数据最多问 3 个关键问题

## 理论依据 · 学术支撑（对应「论文辅助.md」）

> 本节为工作流的方法论底层。可验证的文献、模型、机构来源汇总见 **[论文辅助.md](../_元信息/论文辅助.md)**。

- **资产配置根基**：现代投资组合理论（MPT，Markowitz 1952《Portfolio Selection》均值-方差模型）→ 有效前沿；分散化可消除非系统性风险。CAPM（Sharpe 1964）以 β 刻画系统性风险；APT（Ross 1976）给多因子框架。
- **风险平价补充**：桥水「All Weather」（Risk Parity，1996）按风险贡献而非资金权重配置，直接对应 §3 诊断的「集中度风险」。
- **行为金融护栏**：Kahneman & Tversky 1979 前景理论、Shefrin & Statman 2000 行为组合理论，解释损失厌恶 / 锚定 / 过度自信——支撑本工作流 §9.3「不迎合偏好、区分事实与建议」的红线。
